======================================================================
 راهنمای نصب سایت زهره زارع روی هاست cPanel
======================================================================

این بسته دو بخش دارد:

  • سایت — فایل‌های HTML و CSS و JS. فقط باید در public_html باز شوند.
  • بخش سرور (پوشه‌ی api) — نوبت‌دهی واقعی، ورود با پیامک و پنل
    مدیریت. به PHP و یک دیتابیس MySQL نیاز دارد.

اگر گام‌های ۶ تا ۱۰ را انجام ندهید، سایت باز هم کار می‌کند — فقط
نوبت‌ها به‌جای سرور در مرورگر خود کاربر ذخیره می‌شوند (حالت نمایشی).
برای نوبت‌دهی واقعی آن گام‌ها لازم است.


======================================================================
خلاصه‌ی کارها — یک نگاه
======================================================================

  آپلود سایت (۵ دقیقه)
    ۱. cPanel ← File Manager ← public_html
    ۲. فایل  zohrezare-cpanel.zip  را Upload کنید
    ۳. راست‌کلیک ← Extract   ← بعد خود فایل zip را پاک کنید
    ۴. Settings ← «Show Hidden Files» را تیک بزنید (تا .htaccess دیده شود)

  آماده‌سازی هاست (۵ دقیقه)
    ۵. SSL را روشن کنید تا سایت روی https باز شود
    ۶. MultiPHP Manager ← نسخه‌ی PHP را ۸.۱ یا بالاتر بگذارید

  دیتابیس — همین سه گام (۱۰ دقیقه)
    ۷. MySQL Database Wizard:
         • یک دیتابیس بسازید
         • یک کاربر بسازید و رمزش را کپی کنید
         • تیک ALL PRIVILEGES را بزنید
       ⚠️ اسم‌هایی که cPanel می‌سازد پیشوند دارند
          (مثل zohrezar_zohrezare) — همین اسم کامل را بردارید.

    ۸. در File Manager پوشه‌ی api:
         • از config.sample.php یک کپی بسازید به نام config.php
         • داخلش سه مقدار گام ۷ را بنویسید (name / user / pass)
         • مشخصات پنل پیامک را هم بنویسید

    ۹. آدرس  https://zohrezare.ir/api/install.php  را باز کنید
         • آدرسی که با  key=...  نشان می‌دهد را کپی و باز کنید
         • اگر نوشت دیتابیس ساخته نشده: یا دکمه‌ی «ساختن خودکار
           دیتابیس» را بزنید، یا سه‌کلیکی که خودش نشان می‌دهد را
           انجام دهید
         • دکمه‌ی «ساخت جدول‌ها» ← باید ۹ جدول بسازد
         • دکمه‌ی «افزودن قفل» را هم یک بار بزنید
       ✅ تمام — دیتابیس آماده است. ساخت جدول‌ها کاملاً خودکار است؛
          لازم نیست در phpMyAdmin چیزی ایمپورت کنید.

  تست و امن‌سازی (۵ دقیقه)
   ۱۰. صفحه‌ی  /api/selftest.php  را باز کنید تا همه‌چیز سبز شود
   ۱۱. یک رزرو آزمایشی بگیرید
   ۱۲. این سه فایل را از هاست پاک کنید:
         api/install.php  ·  api/selftest.php  ·  api/sms-test.php

هر گام با جزئیاتش پایین‌تر آمده است.


----------------------------------------------------------------------
گام ۱ — ورود و رفتن به File Manager
----------------------------------------------------------------------
۱. وارد cPanel هاست شوید.
۲. بخش Files ← روی «File Manager» کلیک کنید.
۳. وارد پوشه‌ی public_html شوید.
   (اگر سایت را روی یک دامنه‌ی فرعی نصب می‌کنید، وارد پوشه‌ی همان
    دامنه شوید، نه public_html.)


----------------------------------------------------------------------
گام ۲ — خالی کردن پوشه (فقط اگر سایت قبلی دارید)
----------------------------------------------------------------------
اگر از قبل چیزی در public_html هست (مثلاً صفحه‌ی پیش‌فرض هاست یا
نسخه‌ی قدیمی سایت)، اول از آن یک بکاپ بگیرید و بعد فایل‌های قدیمی
را پاک کنید تا با فایل‌های جدید قاطی نشوند.

نکته: فایل‌های cgi-bin و .well-known را دست نزنید.


----------------------------------------------------------------------
گام ۳ — آپلود و استخراج
----------------------------------------------------------------------
۱. دکمه‌ی «Upload» بالای File Manager را بزنید.
۲. فایل zohrezare-cpanel.zip را آپلود کنید (چند ده مگابایت است،
   کمی طول می‌کشد).
۳. به public_html برگردید و صفحه را Refresh کنید.
۴. روی فایل zip راست‌کلیک کنید ← «Extract» ← تأیید.
۵. فایل‌ها مستقیم داخل همان پوشه باز می‌شوند (index.html باید
   دقیقاً در public_html باشد، نه داخل یک زیرپوشه).
۶. بعد از باز شدن، خود فایل zip را پاک کنید.


----------------------------------------------------------------------
گام ۴ — نمایش فایل‌های مخفی و بررسی .htaccess
----------------------------------------------------------------------
فایل .htaccess با نقطه شروع می‌شود و ممکن است دیده نشود:
   Settings (بالا سمت راست) ← گزینه‌ی «Show Hidden Files (dotfiles)»
   را تیک بزنید ← Save.

مطمئن شوید .htaccess کنار index.html وجود دارد. این فایل مسئول
فشرده‌سازی، کش مرورگر، هدرهای امنیتی و صفحه‌ی ۴۰۴ است.


----------------------------------------------------------------------
گام ۵ — فعال کردن SSL و انتقال به HTTPS  (مهم)
----------------------------------------------------------------------
۱. در cPanel ← بخش Security ← «SSL/TLS Status».
۲. دامنه را انتخاب و «Run AutoSSL» را بزنید و صبر کنید تا گواهی صادر شود.
۳. مطمئن شوید https://zohrezare.ir بدون خطا باز می‌شود.
۴. حالا فایل .htaccess را ویرایش کنید (راست‌کلیک ← Edit) و در بخش
   شماره ۱، علامت # را از ابتدای این شش خط بردارید:

       RewriteCond %{HTTPS} !=on
       RewriteCond %{HTTP:X-Forwarded-Proto} !https
       RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
       RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
       RewriteRule ^ https://%1%{REQUEST_URI} [L,R=301]

۵. ذخیره کنید. از این به بعد همه‌ی بازدیدها به نسخه‌ی امن منتقل می‌شوند.

⚠️ این کار را قبل از فعال شدن SSL انجام ندهید، سایت از دسترس خارج می‌شود.
⚠️ سایت به‌عنوان PWA (قابل نصب روی موبایل) فقط روی HTTPS کار می‌کند.


----------------------------------------------------------------------
گام ۶ — انتخاب نسخه‌ی PHP
----------------------------------------------------------------------
cPanel ← بخش Software ← «Select PHP Version».

نسخه را روی ۸٫۱ (یا بالاتر) بگذارید و مطمئن شوید این افزونه‌ها تیک
دارند:

      pdo_mysql        اتصال به دیتابیس
      curl             ارسال پیامک
      mbstring         متن فارسی
      json             پاسخ‌های سرور

Save را بزنید.


----------------------------------------------------------------------
گام ۷ — ساخت دیتابیس و کاربرش (MySQL Database Wizard)
----------------------------------------------------------------------
این گام سه دقیقه وقت می‌گیرد و فقط یک‌بار لازم است.

۱. در cPanel، بخش Databases ← روی «MySQL Database Wizard» کلیک کنید.
   (اگر «MySQL Databases» بود هم می‌شود؛ ویزارد ساده‌تر است، چون
    خودش کاربر را به دیتابیس وصل می‌کند.)

۲. مرحله‌ی ۱ — نام دیتابیس:
   یک اسم ساده بنویسید، مثلاً:  zohrezare
   cPanel خودش اول اسم یک پیشوند می‌چسباند. یعنی چیزی که واقعاً ساخته
   می‌شود این شکلی است:   zohrezar_zohrezare
   ⚠️ همین اسم کامل (با پیشوند) را یادداشت کنید؛ در گام ۸ باید
      دقیقاً همین را در config.php بنویسید.

۳. مرحله‌ی ۲ — نام کاربر:
   یک اسم ساده، مثلاً:  zohre
   آن هم پیشوند می‌گیرد و می‌شود:   zohrezar_zohre

۴. مرحله‌ی ۲ (ادامه) — رمز عبور:
   روی «Password Generator» کلیک کنید یا خودتان یک رمز قوی بگذارید.
   ⚠️ همین‌جا کپی‌اش کنید و جایی امن نگه دارید. cPanel بعداً رمز را
      به شما نشان نمی‌دهد (فقط می‌توانید عوضش کنید).

۵. مرحله‌ی ۳ — دسترسی‌ها:
   تیک «ALL PRIVILEGES» را بزنید ← Next.
   اگر این تیک را نزنید، سایت به دیتابیس وصل نمی‌شود و خطای
   «Access denied» می‌گیرید.

۶. مرحله‌ی ۴ — تمام. صفحه‌ای می‌آید که می‌گوید ساخته شد.

در آخر این سه مقدار باید دستتان باشد (نمونه):
      نام دیتابیس:  zohrezar_zohrezare
      نام کاربر:    zohrezar_zohre
      رمز عبور:     همان که کپی کردید

نکته: اگر رمز را گم کردید، لازم نیست دیتابیس را از نو بسازید.
cPanel ← MySQL Databases ← پایین صفحه، بخش «Current Users» ← جلوی
همان کاربر «Change Password» را بزنید و رمز تازه بگذارید. بعد فقط
همان رمز تازه را در فایل config.php عوض کنید.


----------------------------------------------------------------------
گام ۸ — فایل تنظیمات سرور (config.php)
----------------------------------------------------------------------
۱. در File Manager وارد پوشه‌ی  api  شوید.

۲. روی فایل  config.sample.php  راست‌کلیک کنید ← Copy ← در کادر
   مقصد بنویسید:   config.php
   (باید در همان پوشه‌ی api ساخته شود.)

۳. حالا روی  config.php  راست‌کلیک ← Edit ← Edit را تأیید کنید.

۴. این چهار سطر را از گام ۷ پر کنید (بقیه را فعلاً کاری نداشته باشید):

      'host'  => 'localhost',                    ← همین بماند
      'name'  => 'zohrezar_zohrezare',           ← نام کامل دیتابیس
      'user'  => 'zohrezar_zohre',               ← نام کامل کاربر
      'pass'  => 'رمز-عبوری-که-کپی-کردید',       ← همین‌جا بین دو '
      'charset' => 'utf8mb4',                    ← همین بماند

۵. چند سطر پایین‌تر، بخش پیامک را هم پر کنید:

      'username' => '...',    ← نام کاربری پنل نیازپرداز
      'password' => '...',    ← رمز پنل نیازپرداز
      'from'     => '...',    ← شماره‌ی خط فرستنده

   فعلاً «enabled» را false بگذارید. پیامک را در گام آخر روشن می‌کنیم
   (هر پیامک هزینه دارد، پس اول اجازه بدهید همه‌چیز تست شود).

۶. Save Changes ← Close.

⚠️ نکات امنیتی
   • فایل config.php رمز دیتابیس و پنل پیامک را دارد. محتوایش را در
     ایمیل، چت یا تیکت پشتیبانی نفرستید.
   • دسترسی وب به این فایل در api/.htaccess بسته شده است؛ برای اطمینان
     می‌توانید یک بار آدرس  https://zohrezare.ir/api/config.php  را باز
     کنید — باید پیام ۴۰۳ (بدون هیچ محتوایی) بدهد.
   • اگر رمزی را اشتباه نوشتید یا فاصله اضافه گذاشتید، در گام ۹ همان‌جا
     پیام خطا می‌گیرید و می‌توانید برگردید و درستش کنید.


----------------------------------------------------------------------
گام ۹ — ساخت جدول‌های دیتابیس (خودکار)
----------------------------------------------------------------------
لازم نیست در phpMyAdmin کاری کنید. این سایت یک نصب‌کننده‌ی خودکار دارد
که فایل api/schema.sql را روی همان دیتابیسی اجرا می‌کند که در
config.php نوشته‌اید.

۱. این آدرس را در مرورگر باز کنید:

      https://zohrezare.ir/api/install.php

۲. صفحه اول یکی از این حالت‌ها است — و هر کدام پیام مخصوص خودش را
   دارد، پس نمی‌مانید که «یعنی چی شد؟»:

   حالت الف) «فایل api/config.php وجود ندارد»
      یعنی گام ۸ انجام نشده یا اسم فایل اشتباه است. برگردید و درستش
      کنید.

   حالت ب) «دیتابیس ... هنوز ساخته نشده است»
      یعنی اسم و رمز درست است، ولی خودِ دیتابیس در cPanel ساخته نشده.
      این صفحه دو راه پیش پایتان می‌گذارد:

        الف) دکمه‌ی «ساختن خودکار دیتابیس» — روی بعضی هاست‌ها جواب
             می‌دهد و دیتابیس همان‌جا ساخته می‌شود. اگر هاست اجازه
             نداد، هیچ چیزی خراب نمی‌شود و فقط پیام می‌دهد.

        ب) راهنمای «۳ کلیک در cPanel» که خودِ صفحه نشان می‌دهد:
             MySQL Database Wizard ← دیتابیس ← کاربر و رمز ←
             ALL PRIVILEGES.
           اسم دیتابیس و اسم کاربری که باید بنویسید را هم همان‌جا
           نوشته (بدون پیشوند، چون cPanel خودش اضافه می‌کند).

   حالت ج) «نام کاربری یا رمز دیتابیس غلط است»
      یعنی user یا pass در config.php با cPanel یکی نیست. صفحه دقیقاً
      می‌گوید چطور رمز را در cPanel عوض کنید.

   حالت د) «کاربر به این دیتابیس دسترسی ندارد»
      یعنی کاربر ساخته شده ولی به این دیتابیس وصل نشده. صفحه می‌گوید
      کجای cPanel باید ALL PRIVILEGES را بزنید.

   حالت هـ) «اتصال به دیتابیس برقرار است»
      حالا نام دیتابیس و فهرست جدول‌های موجود را نشان می‌دهد. چون
      تازه ساخته‌اید، باید بنویسد «هیچ جدولی وجود ندارد» و یک جعبه‌ی
      خاکستری با آدرسی که  key=...  دارد نشان بدهد.

      ⚠️ همین آدرسِ درون جعبه را کپی کنید و باز کنید. آن «کلید» از روی
         رمز دیتابیس شما ساخته شده؛ بدون آن این صفحه کاری نمی‌کند
         (تا کسی غیر از شما نتواند جدول‌ها را دست بزند).

   نکته: صفحه خودش تشخیص می‌دهد کدام‌یک از این حالت‌هاست. لازم نیست
   شما حدس بزنید یا خطای انگلیسی MySQL را ترجمه کنید.

۳. دکمه‌ی «ساخت جدول‌ها» را بزنید.

۴. نتیجه را ببینید:
   • پیام سبز «همه‌ی ۵۴ دستور با موفقیت اجرا شد» (عدد ممکن است کمی
     فرق کند) و فهرست ۹ جدول:
       users · sessions · otp_codes · services · service_variants
       appointments · closed_days · blocked_slots · sms_log
   • اگر جایی قرمز شد، دقیقاً می‌گوید کدام دستور و چه خطایی. پیام‌های
     رایج:

       «Access denied» → نام کاربر یا رمز در گام ۸ غلط است.
       «Unknown database» → نام دیتابیس (با پیشوند) غلط است.
       «command denied to user» → در گام ۷ تیک ALL PRIVILEGES نزده‌اید.

۵. بعد از ساخت جدول‌ها، در همان صفحه بخش «قفل ضدِ رزرو هم‌زمان» را یک
   بار بزنید («افزودن قفل»). با این کار اگر دو نفر در یک لحظه یک ساعت
   را رزرو کنند، نفر دوم پیام می‌گیرد که آن ساعت پر شده. اگر هاست
   پشتیبانی نکند فقط پیام می‌دهد و هیچ چیزی خراب نمی‌شود — سایت بدون
   آن هم کار می‌کند.

۶. دوباره همین آدرس را باز کنید (بدون key). حالا باید پیام سبز
   «اتصال به دیتابیس برقرار است» و ۹ جدول را در فهرست ببینید.

اگر بخواهید همین دیتابیس را بعداً به‌روز کنید، اجرای دوباره‌ی همین
صفحه امن است: جدول‌های موجود دست‌نخورده می‌مانند و هیچ نوبت یا کاربری
پاک نمی‌شود.

روش جایگزین (اگر خواستید): phpMyAdmin ← اول از ستون چپ روی نام دیتابیس
کلیک کنید ← زبانه‌ی Import ← فایل api/schema.sql ← Go.
حتماً اول روی نام دیتابیس کلیک کنید، وگرنه phpMyAdmin پیام «اجرا شد»
می‌دهد ولی جدولی ساخته نمی‌شود.


----------------------------------------------------------------------
گام ۱۰ — بررسی سلامت نصب
----------------------------------------------------------------------
این آدرس را در مرورگر باز کنید:

      https://zohrezare.ir/api/selftest.php

یک صفحه‌ی فارسی می‌آید که تک‌تک موارد را بررسی می‌کند: نسخه‌ی PHP،
افزونه‌ها، اتصال دیتابیس، وجود جدول‌ها، اعتبار پنل پیامک و درست بودن
خط فرستنده.

هر چه قرمز بود را درست کنید تا همه سبز شوند.

بعد این آدرس را باز کنید:

      https://zohrezare.ir/api/health

باید یک متن کوتاه شبیه این ببینید:

      {"ok":true,"time":"...","version":"1.0"}

اگر به‌جایش خطای ۴۰۴ آمد، یعنی mod_rewrite کار نمی‌کند؛ با پشتیبانی
هاست تماس بگیرید.

⚠️ بعد از سبز شدن همه چیز، این سه فایل را از هاست پاک کنید:
      api/install.php
      api/selftest.php
      api/sms-test.php
   هر سه اطلاعات نصب را نشان می‌دهند و نباید در دسترس عموم بمانند.


----------------------------------------------------------------------
گام ۱۱ — تست نهایی
----------------------------------------------------------------------
این آدرس‌ها را یک‌بار باز کنید:

   /                      صفحه‌ی اصلی
   /services.html         فهرست خدمات
   /booking.html          رزرو وقت
   /panel/index.html      پنل کاربری
   /api/health            باید {"ok":true,...} بدهد
   /api/config.php        باید خطای ۴۰۳ بدهد (یعنی رمزها امن‌اند)
   /یک-آدرس-الکی          باید صفحه‌ی ۴۰۴ خودمان بیاید

بعد یک رزرو آزمایشی بگیرید:

۱. با شماره‌ی خودتان وارد شوید — باید پیامک کد تأیید برسد.
۲. یک نوبت رزرو کنید — باید «در انتظار تأیید» بخورد.
۳. با شماره‌ی مدیر وارد شوید و به /panel/admin/ بروید — درخواست باید
   آن‌جا باشد و دکمه‌های «تأیید» و «رد» کار کنند.
۴. همان ساعت را با یک مرورگر دیگر رزرو کنید — باید بگوید در دسترس
   نیست. یعنی نگه‌داشتن ساعت درست کار می‌کند.

اگر تصاویر یا فونت‌ها نیامدند، یک‌بار با Ctrl+F5 صفحه را تازه کنید.


----------------------------------------------------------------------
تنظیمات سایت (بدون نیاز به برنامه‌نویس)
----------------------------------------------------------------------
شماره تماس، آدرس، لینک اینستاگرام و واتساپ، متن‌ها و کد ادمین همگی
در این فایل هستند:

   assets/js/core/config.js

می‌توانید در File Manager همان فایل را Edit کنید و ذخیره کنید.
بعد از هر تغییر، یک‌بار با Ctrl+F5 صفحه را باز کنید.

نکته درباره‌ی پنل: اگر گام‌های ۷ تا ۱۰ را انجام داده باشید، نوبت‌ها روی
سرور ذخیره می‌شوند و ورود با پیامک واقعی انجام می‌شود. اگر نه، سایت
خودکار به حالت نمایشی برمی‌گردد (ذخیره در مرورگر، کد تأیید ۱۲۳۴).

سایت خودش تشخیص می‌دهد: اول آدرس /api/health را صدا می‌زند؛ اگر جواب
گرفت حالت واقعی، وگرنه حالت نمایشی. هیچ تنظیمی برای جابه‌جایی لازم
نیست.


----------------------------------------------------------------------
به‌روزرسانی سایت در آینده
----------------------------------------------------------------------
نسخه‌ی جدید zip را آپلود و Extract کنید و روی فایل‌های قبلی بنویسید.
چون سایت PWA است و سرویس‌ورکر دارد، بعد از آپدیت یک‌بار Ctrl+F5 بزنید
تا نسخه‌ی تازه بارگذاری شود. (تنظیمات کش در .htaccess طوری است که
فایل service-worker.js هیچ‌وقت کش نمی‌شود و آپدیت‌ها می‌رسند.)


----------------------------------------------------------------------
تغییر خدمات سایت (مهم)
----------------------------------------------------------------------
فهرست خدمات در دو جا نگهداری می‌شود و هر دو باید یکسان بمانند:

  ۱. سایت (نسخه‌ی استاتیک):
       assets/js/data/services.js
  ۲. دیتابیس (نسخه‌ی سرور):
       جدول‌های services و service_variants — از روی فایل
       api/schema.sql ساخته می‌شوند.

متن هر خدمت هم در assets/js/data/services.js است (توضیح، مزایا،
نکات مهم قبل از رزرو، مراقبت‌های قبل و بعد، مناسب برای، پرسش‌های
متداول). قیمت‌ها و مدت‌زمان‌ها را می‌توانید از پنل مدیریت هم
ویرایش کنید؛ بقیه‌ی متن‌ها فقط از همین فایل خوانده می‌شوند.

اگر خدمات را عوض کردید و سایت از قبل نصب بوده (کاربر و نوبت
دارید)، این فایل را یک‌بار روی دیتابیس اجرا کنید:

   api/migration-new-services.sql

روش اجرا: cPanel → phpMyAdmin → انتخاب دیتابیس → زبانه‌ی Import
→ انتخاب فایل → Go. اجرای دوباره‌اش هم بی‌خطر است.

این فایل خدمات قبلی را از سایت برمی‌دارد، خدمات تازه را می‌سازد و
اگر خدمتی نوبت ثبت‌شده داشته باشد به‌جای پاک کردن، غیرفعالش می‌کند
تا تاریخچه‌ی نوبت‌های مشتری‌ها سالم بماند.

اگر سایت را تازه نصب می‌کنید، به این فایل نیازی نیست؛ همان گام ۹
(اجرای api/schema.sql) همه‌چیز را می‌سازد.


----------------------------------------------------------------------
تأیید متن پیامک‌ها در نیازپرداز
----------------------------------------------------------------------
سایت شش نوع پیامک می‌فرستد: کد تأیید ورود، رسید ثبت درخواست، خبر به
سالن، تأیید نوبت، رد نوبت و یادآوری.

نیازپرداز متد جداگانه‌ای برای «پترن» ندارد؛ متن کامل با متد معمولی
می‌رود و سامانه آن را با الگوهای تأییدشده‌ی حساب شما تطبیق می‌دهد.
یعنی متن قالب در فایل تنظیمات باید کاراکتربه‌کاراکتر همان چیزی باشد
که در پنل تأیید شده — حتی فاصله و دو‌نقطه. اگر نخواند، خطای ۱۸
(«مغایرت متن با قالب») برمی‌گردد.

متن آماده‌ی هر شش پیامک در این فایل است:

   api/sms-templates-niazpardaz.md

همان متن‌ها را در پنل نیازپرداز ثبت کنید و منتظر تأیید بمانید. بعد از
تأیید هر الگو، مقدار null همان کلید در بخش sms → templates فایل
config.php را با همان متن عوض کنید:

   'received'    => 'درخواست {service} شما برای {date} ساعت {time} ثبت شد! به‌زودی برای تأیید تماس می‌گیریم.',
   'admin_alert' => 'درخواست جدید! {name} - {phone} - {service} - {date} ساعت {time}',
   'approved'    => 'نوبت {service} شما برای {date} ساعت {time} تأیید شد. راس ساعت مقرر می‌بینتون!',
   'rejected'    => 'متأسفانه نوبت {service} شما {date} ساعت {time} تأیید نشد. علت: {reason} تماس: 09178399055',
   'reminder'    => 'یادآوری نوبت {service} شما {date} ساعت {time} منتظر دیدن شما هستیم.',

در این متن‌ها اسم برند «زهره زارع» نیامده؛ هویت فرستنده از خودِ خط
خدماتی معلوم می‌شود، پس در پنل مطمئن شوید عنوان خط خدماتی نام سالن را
نشان می‌دهد. اگر بازبین اسم فرستنده را خواست، «زهره زارع: » را به اول
متن‌ها اضافه کنید و همان متن نهایی را عیناً در config.php هم بگذارید.

هر کلیدی که null بماند، آن پیامک اصلاً فرستاده نمی‌شود؛ پس نه خطای ۱۸
می‌گیرید و نه اعتبار می‌سوزد. کد تأیید (otp) از قبل تأیید شده و
دست‌نخورده بماند.

پیامک‌های کد تأیید و نوبت باید از خط خدماتی بروند، نه تبلیغاتی.

یادآوری (reminder) هنوز زمان‌بند ندارد؛ فقط متنش آماده است. اگر خواستید
یک روز قبل از نوبت خودکار برود، باید یک زمان‌بند روزانه روی هاست اضافه
شود.

تست هر الگو بعد از تأیید (بدون خرج کردن بی‌مورد، با شماره‌ی خودتان):

   api/sms-test.php?tpl=approved&to=09xxxxxxxxx

بالای همان صفحه، فهرست همه‌ی قالب‌ها و متن نمونه‌شان را هم نشان می‌دهد.

نکات امنیتی این نسخه
----------------------------------------------------------------------
• «حالت نمایشی» در این بسته قفل شده است: کد ثابت ۱۲۳۴، نمایش کد روی
  صفحه و نقش مدیرِ محلی فقط وقتی فعال می‌شوند که سرور قطع باشد و
  پرچم demo روشن باشد — و این بسته آن پرچم را خاموش کرده. یعنی اگر
  سرور در دسترس نباشد، ورود اصلاً ممکن نیست؛ هیچ‌کس نمی‌تواند در
  زمان قطعی، خودش را مدیر جا بزند.

• اگر قبلاً کسی (مثلاً موقع تست اولیه) با شماره‌ی مدیر وارد شده،
  برای اطمینان یک‌بار در phpMyAdmin این دستور را اجرا کنید تا همه‌ی
  نشست‌های سرور باطل شوند (همه دوباره وارد می‌شوند، داده‌ای از بین
  نمی‌رود):
      TRUNCATE TABLE `sessions`;

• صفحه‌های نصب و بررسی سلامت حالا قفل دارند و برای بازدیدکننده‌ی
  معمولی ۴۰۳ می‌دهند:
      selftest.php?key=…   ← کلید = ۱۲ کاراکتر اول SHA-256 از «رمز-دیتابیس|zz-selftest»
      install.php?key=…    ← کلید = ۱۲ کاراکتر اول SHA-256 از «رمز-دیتابیس|zz-install»
      sms-test.php?key=…   ← کلید = ۱۲ کاراکتر اول SHA-256 از کلید API پیامک (یا رمز پنل)
  (رمز دیتابیس همان است که در api/config.php گذاشته‌اید.)

• بعد از نصب، اگر همه‌چیز سبز شد، می‌توانید selftest.php و
  sms-test.php و install.php را از هاست پاک کنید — ولی با کلید
  قفل‌اند و مانعی برای ماندنشان نیست.
